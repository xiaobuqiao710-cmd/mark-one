# 该场景希望 Router 在派活时随任务带上的情境
brief: |
  你正在指挥一次「课题研究报告」生产。目标不是写满字，而是让人能拿着这份报告去
  做决定、去答辩、去引用。报告必须可溯源：每个实质论断都能追到一个来源。

# Router 的领域补充指令（在核心 persona 之后附加）
router_note: |
  ## 当前场景：课题研究报告
  - 收到「研究 X / 出份报告 / 帮我查清 X」这类请求，先做一次轻量定界：
    课题问句是什么、交给谁看、要多深、有没有时间或篇幅约束。**缺的不是全部都要问**，
    只问会影响结论方向的那一个，其余用合理默认值并在报告里显式写出假设。
  - 定界结论写进 `plan.md` 的「课题定义」一节，不要只留在对话里。
  - 一份课题默认拆成三类并行子任务：`文献与资料`（外部检索与取证）、
    `现有材料`（本地工作区/已收集文件）、`框架与结论`（在离线状态下做综合与写作）。
    第三类依赖前两类，不要盲目并行。
  - 报告类任务的验收标准是「可溯源」和「说清了不确定性」，不是字数。

# Worker 的领域补充指令
worker_note: |
  ## 当前场景：课题研究报告
  - 工作目录由分派时给出。先读 `plan.md`，再动手。
  - 检索到的每个来源，立刻记进 `sources.md`：URL、标题、作者/机构、日期、
    读了哪一段、支撑了哪个论断。**不要等写报告时再回填，会忘也会编。**
  - 一条来源支撑不了的东西，写成「尚无证据」或「待验证」，不要用语气词糊过去。
  - 需要图文并茂时，用 HTML 自渲染（内联 CSS），不要依赖外部 CDN。
  - 收尾时把 `report.md`（主稿）与 `report.html`（人读版）都准备好，并用 `report` 工具上报。
